# 작업내역서 — 2026-11-03

## 작업 범위

한영 전환 안내, nimf의 Caps Lock 전환, 입력 진단 UI, Plank 위치 복구 UI를 개선했다.
작업 시작 전에 이미 변경되어 있던 카카오톡/Wine 코드·테스트와 관련 README 문구는 이 커밋 범위에서 제외했다.

## 변경 사항

- 한영 전환 UI에 지원 입력기 `nimf, IBus`를 명시했다.
- `xmodmap`의 Lock 목록을 통째로 지우고 재등록하던 동작을 필요한 항목의 추가·제거로 바꿨다.
  원격 X11의 `BadKey`를 잘못된 키 이름으로 재등록하던 오류를 해결하고 modifier 읽기 확인을 추가했다.
- nimf 전환 목록 양쪽에 `Hangul`과 `Caps_Lock`을 등록한다. 기존 설정은 원래 백업을 유지하면서 갱신한다.
- nimf 설정 적용 시 XKB의 Caps Lock 고정 동작을 비활성화하고 이미 켜진 고정을 해제한다.
  변경 전 동작을 백업하고 복원하며, 이후 외부에서 변경한 XKB 동작은 보존한다.
- Cinnamon에서도 로그인 키 설정 감시가 시작되도록 자동 시작 목록을 갱신하고 이전 파일의 소유권 판별을 유지했다.
- 키코드 모니터를 추가했다. 제어판 창의 GTK capture 단계에서 관찰하되 해당 입력칸에 포커스가 있을 때만 표시한다.
  키코드·키 이름·키값·modifier 상태와 누름·뗌을 최근 8개까지 보여준다. 파일에 저장하지 않고 화면 잠금 중 표시를 억제한다.
- 기능키·OSD 탭 상단에 **도크 위치 복구 → Plank 재시작**과 상태 확인 버튼을 추가했다.
  현재 UID·DISPLAY·세션 버스·실행 파일이 일치하는 Plank만 대상으로 삼고 기존 실행 인수를 유지한다.
  작업은 worker에서 수행하고 GTK 갱신은 메인 스레드에서 처리한다. 종료 대기 시간은 제한하며 실패를 화면에 표시한다.
- README에 Plank 수동 재시작, 버튼 사용, Termux:X11 클라이언트의 키 매핑·백업·원복·자동 시작 방법을 기록했다.

## 원격 입력 문제의 확인 결과

서버에서 바꾼 키는 66번이었지만 실제 원격 Caps Lock은 230번 `Caps_Lock`으로 전달됐다.
서버의 XKB 고정 동작을 해제해도 Galaxy S25 → Termux:X11 → ThinLinc 경로에서는 쌍자음·대문자 현상이 남았다.
폰의 Prefer scancodes when possible 옵션도 이미 켜져 있었다.

폰의 Termux:X11에서 Caps Lock을 `Hangul`로 매핑한 뒤 서버 모니터에 `Hangul`이 표시됐다.
사용자가 실제 키로 평자음 `ㄷ`과 영문 소문자 `e`가 정상 입력되는 것을 확인했다.
서버 설정 확인과 클라이언트 물리 입력 확인은 별도의 검증으로 기록한다.

## 검증 및 설치

- 전체 작업 디렉터리에서 `python3 -m unittest -v`: 197개 통과. 별도 작업인 카카오톡/Wine 테스트도 포함한 수치다.
- 커밋할 파일만 분리한 인덱스 스냅샷에서 `python3 -m unittest -v`: 185개 통과.
- Python 컴파일, desktop 파일 검사, 문서의 셸 예제 문법 검사, `git diff --check` 통과.
- HamoniKR 8 / Cinnamon / X11 / ThinLinc에서 제어판과 OSD를 확인했다.
- GTK 버튼을 직접 실행해 중복 클릭 차단, Plank PID 교체, 성공 표시와 화면 하단 위치를 확인했다.
- XKB 동작 적용·읽기 확인·원복과 다른 키 설정 보존을 검증했다. 합성 입력에서 `ㄷ e`와 Caps Lock 꺼짐을 확인했다.
- 사용자의 요청으로 `make install-deb`를 실행해 정상 완료했다. 설치된 GUI·코어·키보드 모듈이 소스와 일치함을 확인하고 제어판을 재시작했다.
- 기존 커널의 msi_ec/0.13 모듈이 이미 설치되어 있어 DKMS 재빌드는 건너뛰었다.
